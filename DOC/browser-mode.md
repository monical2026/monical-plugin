# 浏览器独立模式（0.9.1 引入，当前开发 0.9.4）

新安装默认浏览器模式；从 0.8.x 及更早版本升级、且没有模式选择时保留本机模式。用户可在设置中主动切换，两套服务配置与凭据独立，不自动复制系统密钥。现有学习记录的数据库、扩展身份与 Mac 本机注册标识保持不变。

## 功能边界

已有字幕、笔记、历史与下载导出沿用原实现。浏览器模式负责已配置云端 LLM 的翻译、脉络、问答，以及 Supadata 已有字幕和 YouTube 无字幕生成。B 站仍只支持已有字幕。Chrome 本地翻译仍受设备与浏览器能力限制，不自动付费回退。

系统钥匙串、Windows 凭据管理器与 Codex CLI 仍依赖可选本机组件。0.9.4 浏览器模式 Obsidian 首次连接使用独立扩展页面选择并授权目录，后续记住连接且权限有效时直接导入，不调用本机组件。普通 Windows 用户使用浏览器模式不需要安装 Node、pnpm 或编译器；这不等于已完成 Windows 实机验收。

## 密钥与权限

设置页创建密码（10–200 字符），PBKDF2-SHA256 600,000 次迭代派生 AES-GCM 256 位密钥；每次写入使用随机 IV，本地仅保存盐、IV 与密文。解锁密钥放在 Chrome 受限 session 存储，浏览器会话结束后重新解锁。local/session 的访问级别限制为 TRUSTED_CONTEXTS，不向视频内容脚本暴露密钥。浏览器模式不具备系统钥匙串同等隔离能力；已解锁的扩展上下文可以使用密钥。

密码不保存，忘记后只能重置密钥库并重新填写服务 Key。重置不删除笔记或本机凭据。服务地址变更要求重新提供 Key，避免把已保存 Key 发往另一个地址。保存采用配置修订检查，密文先写成功再更新配置。

manifest 增加可选 HTTPS 主机权限，实际在用户保存或测试所选服务时逐域请求。网络仅允许 HTTPS 公开域名与 443 端口，拒绝 IP、本地域名、重定向，不携带 Cookie。浏览器没有 Node 的 DNS 固定能力，域名校验不能等同于完整 DNS/私网隔离；应使用可信服务域名。请求有超时和响应大小限制，不自动重试计费请求。

## 请求与恢复

设置、面板和历史等扩展页面承担长 AI 请求，避免把完整分析绑定到短生命周期的后台 worker。页面关闭会中断界面流程，不承诺后台继续完成。分析按原有分批规则执行，成功批次保存 24 小时，源稿、模型与配置一致时可在再次主动整理时复用；最终审阅成功后清除批次缓存。

AI 请求用模型配置及输入的摘要记录在途状态。未知结果再次提交前要求明确确认，提示可能重复计费。没有保存完整响应的中断请求不能保证恢复结果。Supadata 生成保留独立确认票据、视频/时长/配置绑定，先保存 submitting 再发送；提交结果未知时不自动重发。

shared/src/ai 是浏览器与本机共用的分析、校验、问答、翻译和生成状态规则；service 的旧入口保持兼容导出。既有长分析函数为保持提示词、输出格式与审阅契约不变而保留，本轮不重排内容。后台和设置的既有长编排入口仅增加必要模式路由，后续拆分需独立回归。

## 分发与验收

`pnpm run package:extension` 输出 `artifacts/releases/VideoNote-0.9.2-chrome.zip`。ZIP 中的 VideoNote 文件夹可供 Chrome 加载，包含 manifest、构建资源、许可证与第三方许可；根部附安装说明。打包不需要本机组件工具链。0.9.2 已发布 [GitHub Release](https://github.com/monical2026/YouTube---/releases/tag/v0.9.2)，下载及更新步骤见[安装指南](user-guide.md)。

用户已确认 0.9.2 可用并授权发布。自动检查和本次用户反馈不等于所有环境均已验证；真实 Chrome 权限、重启、各平台字幕、供应商 API 与旧版升级的完整兼容性仍需持续验证。

## 0.9.4 浏览器知识库连接

首次导入或主动更换知识库时打开独立扩展页，避免视频嵌入 iframe 无法弹出目录选择器。选定并授权后自动导入本次内容，目录句柄保存在独立 IndexedDB（videonote-file-access），不修改笔记数据库。以后由后台从同一扩展来源读取句柄，queryPermission 为 granted 时直接写入，不再选目录或打开独立页；需要重新授权时才打开连接页并由用户点击 requestPermission。不保证浏览器永久保留权限。

目录变更通知通过受限 local 存储发送名称与更新时间，导出窗口收到后刷新显示。浏览器不提供绝对路径或父目录访问，不能沿父级寻找 .obsidian，请用户确认目标属于知识库。取消和拒绝授权不写文件，写入和关闭流成功后才显示已导入。

导出快照暂存在受信任的 Chrome session 存储，随机请求 ID 放在扩展页地址中，正文不放 URL；成功清理请求，30 分钟后过期，打开新请求时清理过期数据，浏览器会话结束后清除。过期或关闭页面可从原视频再次导出，不改笔记原始数据。

同视频以文件名中的视频标识判重；确认后选择新副本名。扩展页面之间使用 Web Locks 串行写入，并在创建前复查文件存在。浏览器 API 没有原子 exclusive-create，不能保证与其他本机程序同时创建完全同名文件的竞态隔离；写入失败可能留下空文件，不自动删除归属无法确认的文件。

文件职责：browser-obsidian.ts 管理浏览器目录授权与判重写入；browser-export-request.ts 管理暂存请求；BrowserObsidianPage.tsx 提供独立导出页；ExportDialog 按模式选择导出路径。shared/export-filename.ts 共用安全文件名，不改变本机命名规则。

## 0.9.4 脉络来源校正与首次安装

分批分析及全片复核明确提供当前有效来源 1–N、首尾覆盖与相邻编号规则。保留严格校验；已完成的模型回复若仅触发连续范围校验失败，最多追加一次带具体编号错误的校正请求，该请求可能额外计费。校正后仍失败立即停止，不猜测或扩写主题范围，不覆盖旧结果。网络失败、鉴权失败、未知提交结果及非 JSON 不触发此校正。浏览器分析进度签名增加契约版本，旧缓存不复用，已保存脉络不清除。

首次 runtime.onInstalled(reason=install) 自动打开设置页，update 等原因不打开；保留原升级服务模式兼容。打开失败仅设置工具栏说明，不重复弹窗。

新增职责：browser-directory-store.ts 持久化句柄；background/browser-obsidian.ts 核对权限并直接写入；first-install.ts 管理首次打开；shared/ai/analysis-coverage.ts 管理编号约束与一次校正。ExportDialog（超过 300 行）保留原选择、重复确认和下载编排，新增文件写入/持久化/后台逻辑均独立，避免本轮重排原有下载交互。background/index 保留统一来源校验入口，新业务逻辑已拆出。
