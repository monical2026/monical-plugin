## 规则及影响

- 短引用最多保护 240 字符，长引用内部允许句末分段；修复 Greg 28:08–42:49 的无界保护。保留缩写、小数、网址与短引用处理。
- 超过两倍软目标的无可靠句末单元额外搜索英文转折／新分句结构；禁止明显未完成的介词、从句引导词、引述动词等后断开。分句候选增加 0.35 代价，继续向后比较组合，不按字符硬切，也不补写标点或原话。
- `>>` 需要会话上下文支持：来源条目开头、句末后，或已确认的重复会话标记惯例，再检查后文开头。技术文本中的常见位移表达式不当换人；不识别真实人物身份。
- 算法版本升到 2。恢复旧记录的来源字符范围与时间，而非把旧巨段整体当成新来源。来源范围与文本不匹配时降级到现有文本及粗时间，避免旧元数据覆盖正文。
- 手改段落作为边界保留，正常打开不改缓存；显式预览／应用时保留笔记、未变段标识及译文。改变边界的新段译文留空，旧稿及译文进入备份，可恢复。
- 推断分句在预览显示说明，仍超过两倍软目标的段落在预览及正文显示偏长提示。SaT、音频检测与新依赖均未引入。

## 实际验证

- 修复前新增四类核心用例均失败，覆盖错配引号、无标点巨段、问答轮次、旧来源时间恢复；修复后通过。
- `pnpm run check` 通过：类型、lint、格式、19 个文件共 109 项单元测试，以及扩展和本机组件构建。首次 lint 暴露不必要的正则转义，已修正并重跑完整检查。
- 额外本地真实稿件回放 1 项通过，覆盖三组数据。先用保留的版本 1 重现原导出分段，再验证版本 2 从原始条目和旧版本来源范围得到相同原文、时间与来源映射；忽略空白后文本完全一致，来源子串与原始范围逐个一致，标识无重复，再次预览稳定，备份恢复一致。
- 同一回放中纯重组耗时约 14.2／3.7／0.5ms，仅代表这三组本机输入，不代表 Chrome 界面端到端性能或全部数据规模。
- 人工抽查了 Rebecca 开头／长段、Greg 9:01 附近及原巨段开头、Jessica 10:51 附近；这是有限抽查，不是全文句子准确性验收。
- 本轮未执行浏览器交互、真实 Chrome 视频播放、翻译服务或音频校对；用户最终阅读体验待验收。没有 Git 提交和推送。

本地回放资料及完整英文预览在已忽略的 artifacts/segmentation-audit/。它们是私人诊断产物，不加入共享夹具。

## 用户复测步骤

1. 在 Chrome 扩展管理页重新加载扩展，确认版本 0.1.8，并刷新已打开的 YouTube 视频页。
2. 对原来测试的三个视频点击“重新分段”，先看预览，再应用；无需先恢复原始逐字稿，已有来源范围会用于升级。
3. 需要中文时点击“补齐本地翻译”；这次修改没有预先调用任何翻译服务。
4. 重点检查缺标点段的衔接、仍偏长提示及点击跳转。来源只有整条时间时可能重叠。旧内容可在预览窗口恢复。

本轮没有改本机服务行为，不需要重新登记组件，不重新输入 API key。最终 Chrome 人工验收后才能提交／推送。
