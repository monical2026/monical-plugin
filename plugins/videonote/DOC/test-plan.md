# VideoNote测试方案

> 状态：测试方案草案，尚未开发、尚未执行测试。本文中的“预期结果”是验收要求，不是已验证结果。
> 测试依据：[实施计划](./PLAN.md)、[设计说明](./design.md)、[技术方案](./technical-design.md)及用户后续确认的需求。文件名或方案变化时同步修正引用。
> 执行记录统一填写到 [测试反馈](./test-feedback.md)。本文件不预填“通过”。

## 一、测试目标与边界

第一版在用户当前电脑和 Chrome 上验证完整的 YouTube 阅读与记录流程，重点排除记错视频、摘错时间、笔记丢失、个人修改被覆盖等问题。

- 已确认范围：仅根据逐字稿整理，不分析画面；个人使用；原文、中文、中英双语模式；中文 AI 内容；逐字稿联动、编辑、笔记、导出；视频切换后内容同步切换；关闭插件面板时仍可使用快捷键记录；非 YouTube 网页不显示插件界面。
- 已确认支持普通点播页面：`https://www.youtube.com/watch?v=VIDEO_ID`；Shorts、正在直播和站外嵌入明确留到后续。直播回放、移动版域名、音乐站点等不因返回文字就宣称已兼容；普通视频全屏与剧场表现仍需验证。范围外功能不用实现，但不误注入、不请求、不串数据的检查必须执行。
- “关闭插件”在本方案中指关闭面板，扩展仍安装并启用；扩展被停用或卸载时，不要求快捷键可用。
- 自动化替身用于稳定重现响应乱序、服务失败、时间边界等情形；真实视频与真实服务用于验证实际集成。两者分别记录，不能互相替代。
- 划词粒度、中文补齐、原文修改后译文处理、快捷键等按 design.md 和 technical-design.md 的明确设计默认验证，人工验收时再判断是否符合使用习惯；不能把实施默认写成用户已确认。若两文件没有规则或相互冲突，相关用例先阻塞并澄清。费用上限没有确认时不擅自进入付费处理。

## 二、优先级和结果定义

| 标记 | 含义 | 发布要求 |
| --- | --- | --- |
| P0 | 数据丢失、跨视频混入、私密信息泄漏、主要流程无法完成 | 必须修复并回归 |
| P1 | 核心功能或常用交互不符合已确认需求 | 必须修复并回归 |
| P2 | 边缘状态、视觉一致性或补充质量要求 | 纳入范围的用例仍必须完成；不能自行跳过 |

结果只允许填写：未执行、通过、失败、阻塞、不适用。

- **通过**：完成所有步骤，实际结果满足预期，有足够证据。
- **失败**：已执行，存在可复现的不符合项，关联问题编号。
- **阻塞**：缺少凭据、确认、可用样本或依赖，未获得实际结论。
- **不适用**：已有明确范围依据，并记录原因；不能用来掩盖未实现的已确认功能。
- 自动化通过不等于人工通过；模拟服务通过不等于真实服务通过；文档检查通过不等于产品测试通过。

## 三、执行环境与样本

### 1. 每轮必须记录的环境

- 操作系统及版本、Chrome 版本、扩展版本、构建标识及 Git commit；未提交时记录源码变更摘要或构建校验值。
- 屏幕分辨率、浏览器缩放、YouTube 浅色或深色模式、扩展主题、语言模式、快捷键实际绑定。
- 本机组件运行状态、版本、服务适配器和模型标识；只记录凭据是否配置，不记录凭据内容。
- 网络条件、缓存是否命中、测试账号与样本是否可访问、是否有广告；账号记录使用非敏感代号。
- 自动化依赖和命令由实际工程确定后填入，不提前编造可运行命令。

### 2. 样本清单

| 样本编号 | 内容 | 用途及要求 |
| --- | --- | --- |
| F01 | 人工制作的带时间英文字幕，附预期分段和中文译文 | 完整句、缩写、标点、Unicode、空白、时间边界；无需外部请求 |
| F02 | 碎片化自动字幕与重复、重叠片段 | 去重、合并、非负时长及时间映射 |
| F03 | 超长句、长停顿、缺少标点和较粗时间戳 | 分段容错与精度限制，不制造不存在的词级时间 |
| F04 | 视频 A、B 的可控响应，支持延迟、逆序、取消后继续返回 | SPA 导航、旧请求隔离及多标签竞态 |
| F05 | 外部服务响应替身 | 成功、异步任务、认证失败、限流、超额、超时、畸形响应、部分结果 |
| F06 | 原文和译文多个版本、已摘录笔记与未保存草稿 | 差异提示、更新引用、个人内容保护 |
| F07 | 含 HTML、脚本样式文本、Markdown 符号、异常文件名及伪指令的文字 | 安全呈现、导出、AI 不可信输入；全部使用测试字符串 |
| F08 | 大体量逐字稿和多条笔记 | 长列表及搜索、编辑、导出压力；先记录实际条数和体积 |
| R01 | 真实英文普通视频，具有可获取字幕 | 记录 URL、标题、时长、字幕类型、人工参考时间点 |
| R02 | 真实无可用字幕的普通视频 | 人工核实并记录字幕状态，用于外部转写；失败时如实记录 |
| R03 | 真实英文长视频 | 时长与类型由用户常看视频确定，未取得样本前保持待补 |
| R04 | 实际有广告或平台状态变化的视频 | 有条件时验证；无法稳定重现时先用替身覆盖，再记录真实覆盖缺口 |

真实样本可能失效。每轮先检查可访问性，不把视频被删除或地区限制记成插件已通过。仅保存测试所需的截图和文字片段；不得把完整个人笔记或凭据上传到公共仓库。

## 四、测试顺序与阶段出口

1. **静态检查与构建**：类型、格式、构建、Manifest 权限、依赖和敏感信息检查。失败时先修复，不开始发布验收。
2. **本地模块测试**：分段、时间定位、版本比较、存储、导出等稳定逻辑，使用固定样本。
3. **服务契约与组件集成**：验证请求、响应、语言、缓存、错误和乱序；模拟状态与真实接口分开。
4. **受控端到端测试**：可控播放器和响应替身覆盖竞态、广告状态、跨标签、崩溃恢复等难稳定复现的场景。
5. **真实 Chrome / YouTube 测试**：加载实际扩展，使用真实服务完成有字幕与无字幕流程，保留证据。
6. **人工验收**：用户亲自在当前电脑上完成核心使用流程，对指定构建明确反馈是否通过。
7. **问题修复与回归**：每个问题记录复现、原因、变更和回归结果；修复涉及已验收行为或更换构建时，重新取得该构建的人工确认。
8. **Git 与 GitHub 交付**：满足本文最后的门槛后再提交和推送。

## 五、具体测试用例

### A. 页面范围、入口与导航

| 编号 | 优先级 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| NAV-01 | P1 | 在扩展启用状态打开普通 YouTube 视频页，检查视频下方入口，点击并关闭面板，再次打开 | 只有一个小入口；位置不遮挡视频、标题或原生操作；可反复打开，不重复挂载 |
| NAV-02 | P0 | 打开搜索引擎、文档站点和本地页面，尝试预定快捷键 | 不注入面板、浮钮、笔记弹窗或样式；不为这些页面调用字幕或 AI 服务 |
| NAV-03 | P1 | 从视频页进入 YouTube 首页、搜索、频道页，再返回视频 | 非支持页面移除视频专用 UI 并停止播放绑定；返回后按当前视频重新建立上下文 |
| NAV-04 | P0 | 视频 A 完成加载后，点击站内推荐跳到视频 B；用前进、后退返回 A | 逐字稿、AI、笔记、时间及高亮均对应当前视频；无需手动刷新；可复用各自缓存 |
| NAV-05 | P0 | A 请求延迟时切 B，再切 A；让第一次 A 响应最后返回 | 仅当前有效任务可更新当前界面；旧响应不能覆盖新的编辑、状态或新一轮 A 数据 |
| NAV-06 | P0 | 同时打开 A、B 两个标签，交替激活、播放和按快捷键 | 快捷键只作用于当前有效标签；数据按视频隔离；后台标签响应不改变当前笔记弹窗 |
| NAV-07 | P0 | 在 A 的笔记弹窗写未保存内容，随后站内跳到 B，再执行保存或关闭 | 草稿保持绑定创建时的 A、时间和摘录；不保存进 B；离开时按确定的草稿恢复规则处理 |
| NAV-08 | P1 | YouTube 页面局部重绘、窗口缩放、切影院模式后再次打开 | 入口和面板不重复、不消失；卸载的旧事件监听不会造成多次跳转或多条笔记 |
| NAV-09 | P1 | 普通视频→Shorts→watch URL 正在直播→普通视频，以及站外嵌入；各处按快捷键 | 范围外不显示入口或笔记窗、不获取字幕或触发 AI；及时清理旧 UI，保留草稿；返回普通视频恢复正确内容，不仅按 watch 路径误判直播 |
| NAV-10 | P1 | 同一视频改变播放列表参数或通过带时间链接定位 | 仍归属于同一视频；不重复抓取整份逐字稿，笔记和缓存保持正确关联 |

### B. 获取、服务契约与加载

| 编号 | 优先级 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| API-01 | P0 | 运行有字幕真实样本，记录响应类型、语言、时间单位及转换结果 | 正确关联视频 ID；原文、起始时间和时长可用于同步；真实调用证据不含凭据 |
| API-02 | P0 | 运行无字幕真实样本，完成允许范围内的转写和结果读取 | 明确区分原生字幕、生成字幕与任务等待；转写完成后可播放定位；失败不展示伪造稿件 |
| API-03 | P1 | 用替身返回异步任务、排队、处理中、完成，以及任务失败 | 只展示真实阶段；轮询有间隔和上限；完成读取一次；失败可理解并可重试 |
| API-04 | P1 | 分别返回未知进度及可计算翻译段数 | 未知进度用不确定进度条；已知进度按真实完成量计算；不会假装达到 100% |
| API-05 | P0 | 返回无凭据、无效凭据、额度不足及 429，反复点击重试 | 给出对应中文状态；不无限循环、不自动进入付费；尊重可用重试信息并防重复请求 |
| API-06 | P1 | 模拟离线、请求超时、服务 5xx、本机组件请求中崩溃，恢复后重试 | 已保存内容仍能访问；错误不清空笔记；恢复后可继续，不产生重复摘录 |
| API-07 | P0 | 并发打开同一视频、重复点击加载，在等待中切页 | 不因重复操作重复创建同一处理任务；迟到结果只写正确视频和版本；记录实际调用次数 |
| API-08 | P1 | 返回缺失文本、非法时间、乱序片段、意外语言或部分结果 | 校验失败或明确降级；不崩溃、不把非中文标成译文；部分结果状态不冒充完整 |
| API-09 | P1 | 请求语言不可用并发生服务回退 | 根据实际返回语言标识处理，不假定请求中文就已取得中文翻译 |
| API-10 | P1 | 用已处理视频再次进入，随后修改本地译文并再次进入 | 可复用对应缓存；不多扣额度；本地手动修正不被缓存刷新或迟到翻译覆盖 |
| API-11 | P1 | 组件未安装、版本不兼容、启动失败及正常空闲时打开设置并获取字幕 | 区分安装与启动错误；空闲自动按需启动，不误报离线；不要求配对码，旧笔记仍可编辑 |

### C. 分段、翻译与显示模式

| 编号 | 优先级 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| TXT-01 | P1 | 输入 F01–F03，与人工确定的预期边界比较 | 尽量保留完整句；合并碎片且不丢词、不重复词；过长段落有控制；时间单调且有效 |
| TXT-02 | P0 | 分段后逐项追溯原字幕时间，再编辑某段文字 | 稳定来源关联保留；文字变长或变短不会按字符比例随意改写原有时间 |
| TXT-03 | P1 | 原文模式首次启动且没有翻译缓存 | 获取原文后即可阅读，不为整段中文翻译等待；界面只显示原文 |
| TXT-04 | P1 | 依次切换中文、双语、原文，覆盖翻译未完成和完成状态 | 只展示所选模式；双语在对应段内成对显示；模式切换不重复发起同样任务 |
| TXT-05 | P1 | AI 内容已生成后连续切换三种逐字稿模式 | AI 保持中文和原有内容，不自动重新生成；通过请求记录核实 |
| TXT-06 | P1 | 翻译包含人名、术语、数字、否定、方法步骤的参考段落 | 人工核对意思、数字、否定关系和术语；错误逐条记录，不用主观“整体不错”替代结果 |
| TXT-07 | P0 | 编辑中文，在保存同时让旧翻译响应到达，刷新页面 | 保存的中文保持；不发起自动重翻译，不被旧响应覆盖 |
| TXT-08 | P1 | 编辑原文并查看已有译文，再主动重译 | 按设计默认保留原译文并标记待核对；只有主动操作才重译；人工验收判断此默认是否符合预期 |
| TXT-09 | P1 | 测试没有字幕的时间空隙、纯音乐、超出最后一段的时间 | 不高亮无关内容，不伪造补全文字；粗时间戳的精度限制记录清楚 |
| TXT-10 | P1 | 搜索中英文关键词，切换上一条/下一条，再点击命中段落 | 搜索只覆盖实际取得的文字，数量准确；定位命中不改变播放时间，点击段落才跳转播放 |

### D. 播放联动、自由浏览与选词

| 编号 | 优先级 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| PLAY-01 | P1 | 以 1×、0.5×、2× 播放，观察段落起止边界并拖动进度条 | 高亮按实际视频时间更新，倍速不会累计漂移；边界无重复高亮 |
| PLAY-02 | P1 | 开启跟随后持续播放，再用滚轮、触控板和滚动条浏览远处 | 跟随时当前段可见；手动浏览进入自由状态；高亮继续更新但列表不被拉回 |
| PLAY-03 | P1 | 在播放和暂停两种状态下自由滚动后点击底部“跟随” | 列表回到当前实际时间段，恢复跟随；点击跟随不改变视频时间或暂停状态 |
| PLAY-04 | P1 | 单击历史或未来段落文字，包括视频原为暂停状态 | 跳到该段起始时间并开始播放，高亮立即一致；播放被浏览器拒绝时有实际状态反馈 |
| PLAY-05 | P0 | 拖动选择一段及跨段文字，释放后点击“做笔记” | 选词不触发视频跳转；入口不丢失选区；摘录内容符合已确认的选区和双语对齐规则 |
| PLAY-06 | P1 | 在逐字稿编辑框、笔记编辑框及图标上点击和选词 | 编辑或操作按钮不冒泡触发段落播放；键盘输入不意外控制 YouTube 播放 |
| PLAY-07 | P0 | 模拟并实测广告进入/结束期间的高亮、跟随、快捷键和跳转 | 不将广告时间写为正片笔记；无法确认正片位置时暂缓操作并提示；恢复后重新读取正片时间 |
| PLAY-08 | P1 | 使用键盘翻页或聚焦逐字稿，滚动面板外页面 | 自由浏览与跟随切换基于实际阅读操作；页面滚动不会错误修改笔记时间 |

### E. 笔记创建、编辑与版本更新

| 编号 | 优先级 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| NOTE-01 | P0 | 面板打开时按快捷键，输入理解和疑问，保存 | 摘录触发瞬间的播放片段，固定视频和时间；双语、个人文字和来源完整保存 |
| NOTE-02 | P0 | 关闭面板后播放并按快捷键；另测从未打开面板且尚无字幕的情况 | 可直接进入笔记流程；已缓存时可摘录；未加载时显示获取/补齐状态，不编造内容；等待期间时间和视频保持绑定 |
| NOTE-03 | P0 | 快捷键创建后等待较久再保存，其间继续播放、暂停及拖进度条 | 摘录仍属于触发时的位置；个人想法不被后续当前段替换 |
| NOTE-04 | P1 | 原文模式无中文时摘录，再模拟译文成功、失败和稍后重试 | 先保存来源、时间与草稿输入，成功后补齐引用；失败可重试，不覆盖人工修正；未完成译文不冒充成功 |
| NOTE-05 | P1 | 三种显示模式中分别选词摘录，含跨段选区 | 按确认规则保存双语及所选范围；不能把整段译文伪装成精确选词翻译；必要的上下文可区分 |
| NOTE-06 | P0 | 保存笔记后重新打开编辑，修改想法、疑问和允许编辑的引用字段，再刷新 | 改动持久保存，其他字段不丢失；取消编辑不覆盖已保存版本 |
| NOTE-07 | P1 | 留空理解或疑问、输入中文长文、多行、表情及英文，保存后再编辑 | 选填项不强制输入；文本原样保存；中英文无需常驻标签；图标可辨认且有辅助名称 |

## 六、人工端到端验收脚本

人工必须使用实际扩展和真实视频完成，不能只看自动化截图。依次执行并逐项记结果：

1. **HUMAN-01｜进入与阅读**：从普通视频下方小按钮打开，观察加载，切换三种模式，核对是否只展示当前模式；听一段英文并检查中文是否帮助理解。
2. **HUMAN-02｜播放联动**：播放、暂停、手动翻到远处、点击“跟随”、点击另一段文字；确认行为与预期一致且不打断自由阅读。
3. **HUMAN-03｜两种摘录**：关闭面板按快捷键记一条，打开后划词记一条；分别写理解和疑问，再修改已保存笔记。
4. **HUMAN-04｜来源纠错**：修改一段译文，查看旧笔记差异；分别试保留和更新，确认自己的文字不变。
5. **HUMAN-05｜视频切换**：A→B→A，等待中切换一次，两个标签交替记录一次；确认每条笔记、稿件和 AI 属于正确视频。
6. **HUMAN-06｜保存与带走**：刷新、重启 Chrome、导出完整稿件和笔记，检查文件实际内容与时间链接。
7. **HUMAN-07｜AI 与无字幕**：核对真实 AI 总结、结构、金句、方法及切片建议；验证一个真实无字幕视频，不能以替身代替。
8. **HUMAN-08｜使用感受**：在用户常用窗口和主题下评价字号、行距、入口位置、弹窗大小及操作负担，记录具体不顺手的步骤。
9. **HUMAN-09｜配置服务**：从齿轮进入独立网页，完成组件安装检测、钥匙串授权、LLM 及 Supadata 配置、指定模型连接测试、任务模型选择和保存；重新打开确认持久化，执行短翻译和 AI 请求核实真实生效，反馈设置是否易懂；完全退出并重启 Chrome，换视频再次调用，确认无需重填 API key，记录实际系统提示次数及场景。

人工验收记录必须包含日期、测试人、对应构建、通过/未通过/待确认，以及用户实际反馈原文或可定位的证据。没有明确反馈时保持“待确认”。

真实 Chrome / Windows 人工验收：解压 ZIP 选择 VideoNote 目录加载；无 Node/组件时读取字幕、编辑保存、刷新回看和文件导出；设置密码、授权真实服务域名、保存 Key、重启解锁后翻译/整理/问答；拒绝授权不发请求；无字幕先确认再提交；中断任务不自动重复计费。Mac 旧安装升级仍读取原本机配置，主动切换浏览器模式后两套配置独立。Codex 仍需组件；0.9.3 Obsidian 浏览器导出按下列专项验收。


## 0.9.3 浏览器 Obsidian 与脉络

- 无本机组件，从视频内嵌面板打开独立导出页，选择中文/空格目录，拒绝和取消授权不写入；成功 Markdown 含已选内容。
- 同视频重导出和改标题均提示重复；取消不动旧文件，确认生成副本；多个导出页不互相覆盖，写入失败不报成功。
- 实际 videoActions 经 RPC 进入 browserService，使用模拟 API 返回经过真实解析的分析及复核结果；断言不调用本机消息。保留已有脉络失败、切换视频及来源契约回归。
- Windows Chrome 原生目录授权、真正 Obsidian 收录及真实模型分别人工验收；夹具与模拟请求不算实机通过。


## 0.9.4 范围校正、持久连接和安装入口

- 复现首主题从 2 或 0 开始、末尾漏段、越界；明确范围校正成功后映射到真实字幕 ID，连续失败最多两次调用，网络或非 JSON 不触发补发；分批和复核均覆盖。
- 真实 videoActions → browser RPC → 模拟模型的范围错误校正及复核成功；旧结果、视频切换、源稿变动契约继续回归。
- 首次连接知识库后本次自动导入；刷新页面可读取持久句柄，后台权限有效直接写入；失效/拒绝不写入，重复确认副本，更换目录取消保留旧连接。
- 首次 install 打开设置一次；update/chrome_update 不打开；失败不重置数据。Windows 首次安装与真实目录授权另行人工验收。


## 0.9.5 脉络诊断回归

- 实际 videoActions→rpc→browserService→模拟模型，复核返回错误字段时保留旧结果、准确记录字段与网络阶段、不额外重发。
- 完整/章节/提炼请求各自只有本轮输出模板；初次生成仍保留完整脉络规范。
- 诊断不含测试 Key、原始字幕、私人文本或完整模型返回；记录缺失/null/类型/长度错误。
- 存储失败仍完成原业务且能复制内存副本，旧任务迟到不覆盖新任务，不同视频隔离，容量受限，刷新后读取。
- 真实 React 复制按钮：剪贴板成功提示、拒绝时只读文本可手动复制；本地夹具不代替 Windows 扩展实机与真实模型复测。


## 0.9.6 前置知识对象回归

- 复现旧 prerequisites 数字数组校验拒绝对象；验证显式索引、原条目唯一精确匹配、数字与对象混合，保留原正文。
- 越界、负数、小数、字符串索引、额外字段、正文改写、缺字段、歧义、重复引用仍拒绝。
- 实际 videoActions→browser RPC→模拟模型→全片复核→保存成功，调用次数不增加；长片拆分提炼采用同一规则。
- 未知对象的结构诊断只包含允许字段类型，不泄漏正文、未知键名或凭据。


## 0.9.7 不完整合并回归

- 实际 videoActions→浏览器 RPC→模拟模型→复核保存：仅返回多项 indexes 的知识与方法保留全部原条目、正文及限制，发起原有两次请求，无额外重试，诊断有 review.merge.preserved。
- 只补一部分正文、空数组或空白文本时丢弃局部改写，保留原条目与出处；重复与非法索引仍失败且诊断 issues 非空。
- 完整合并原行为继续通过；界面展示新增保留提示且不意外展示旧来源过滤警告，存储 warnings 保留。
