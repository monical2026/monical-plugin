# VideoNote设计规范

0.6.1 当前界面增量：B 站普通视频共用逐字稿／脉络／笔记，入口位于视频工具栏，面板置于右栏。中文原稿只显示一份内容，收起语言切换、LLM 翻译及空译文编辑框；外语按钮改为原文／中文／双语。中文金句按来源原话展示与复制；历史目录标记 B 站或 YouTube。实现与验收边界见 [多平台适配](multi-platform-adaptation.md)，下述第一版 YouTube 范围属于原始设计，不覆盖该增量。

> 状态：设计方案，尚未实现，也未经过真实页面或用户验收。
> 本文与 [实施计划](PLAN.md) 配套。用户已确认的行为具有优先级；配色、尺寸、布局、图标造型和栏目名称均为本次补齐的设计默认，可根据原型与人工测试调整。
> 第一版以当前电脑的 Chrome 和普通 YouTube 视频页为验证基线；不把下面的像素值或效果描述当成已完成的结果。

## 一、使用目标与边界

让用户始终看清三件事：视频正在讲什么、自己在读哪里、刚记下的内容是否已经保存。视频与学习内容同时可见，常用动作不超过一次明确点击或一个快捷键。

- 第一版支持普通 `https://www.youtube.com/watch?v=...` 视频页。用户已确认 Shorts、正在直播及其他网站嵌入的播放器留到后续，页面不显示入口、面板或快捷笔记窗。电视版等其他页面不宣称支持；直播回放与普通视频全屏另按能力实测，不误写为用户已排除。
- 其他网站不注入入口、面板、浮层或快捷笔记窗口。YouTube 首页、搜索等非视频页面也不显示页面内插件界面。
- Chrome 自己管理的扩展工具栏图标不属于本插件可以按页面强制隐藏的范围，不将“其他网页不显示”误写成隐藏该图标。
- 页面在不同视频之间切换时，视频标题、逐字稿、AI 内容和笔记按视频标识切换，旧视频内容不能短暂显示成新视频的内容。
- 面板关闭只表示收起阅读界面。在支持的视频页，快捷键依然可以创建笔记；此过程不自动打开完整面板。

第一版 AI 区域注明“基于逐字稿”；不提供画面分析、截图分析或视频模型配置入口。讲解文字缺少操作细节时显示简短的来源不足说明，不以猜测补齐教程。

## 二、视觉风格

采用安静的阅读工具风格：中性背景、清晰正文、少量靛蓝强调。避免大面积渐变、玻璃背景、发光描边和宣传式空白。保留 YouTube 原有播放器和页面层级，插件通过统一边框、字重与间距形成一个完整阅读区域。

- 正文阅读优先，时间戳和工具保持次要层级。
- 字幕采用宽松行距；金句和方法卡片使用紧凑的轻边框，不堆叠厚阴影。
- 活动状态同时使用颜色、竖线或文字提示，不单靠颜色表达。
- 双语直接上下排列，不常驻显示“英文原文”“中文翻译”。英文在上、中文在下，通过字重和间距区分。
- 理解与疑问使用线框 SVG 图标，无常驻栏目文字。悬停和键盘聚焦显示中文提示，辅助技术能够读取名称。

### 2.3 间距、形状与图标

- 间距基线：4、8、12、16、20、24、32px。面板左右内边距 16px，卡片内部 12px，卡片之间 12px。
- 面板圆角 14px，卡片 10px，按钮和输入框 8px；分割线 1px。
- 正常图标 18×18px，入口图标 16×16px。统一 `viewBox="0 0 24 24"`、`stroke="currentColor"`、1.75px 线宽和圆形端点。
- 图标按钮可见尺寸不必很大，但点击区域至少 32×32px，主要入口至少 36px 高。
- 面板仅使用轻阴影；浮窗阴影建议 `0 12px 36px rgba(0,0,0,.16)`，深色对应提高到 `.32`。
- 理解默认使用线框灯泡，疑问默认使用带问号的对话框；两者可由轮廓区分，不依赖黄色或其他颜色。
- 阴影、图标形状和以上色值为设计默认，尚无原型偏好证据。

## 三、页面入口与布局

### 3.1 视频下方的小入口

入口文字暂定“学习笔记”，左侧放简洁的文档播放图标。默认高度 36px，左右内边距 12px，图标与文字间隔 6px，圆角 18px，宽度由文字决定，约 100–116px。

- 优先在播放器下方、视频信息与操作区域旁的可用位置增加独立入口，不能覆盖点赞、分享、订阅或视频标题。
- “空缺处”不是假定永远存在的固定屏幕坐标。原操作行没有空间时，在其下方插入插件自己的窄入口行，与原内容间距 8px。
- 不移动或删除 YouTube 原有操作。入口只挂载一次，视频切换后继续保持唯一。
- 点击打开面板，再次点击收起。图标和 `aria-expanded` 同步变化，入口保持可见，不通过展开整个面板来关闭。
- 面板隐藏后仍可用快捷键摘录。首次创建成功时使用一次简短提示“笔记已保存，可在学习笔记中查看”，不反复教育用户。

### 3.2 宽屏默认布局

默认采用页面内面板，位于播放器右侧推荐区域；面板打开时，让推荐内容顺延到面板之后，关闭时恢复页面布局。不能用悬浮层盖住播放器、字幕或原操作区。

- 视口宽度至少 1280px 且实际可用右侧空间至少 380px 时启用右侧布局。
- 默认宽度 440px，可拖动调整为 380–560px；不能让面板把播放器压缩至不可阅读，应按实际空间切换布局。
- 面板顶部随页面布局定位，滚动后可吸附在导航栏下方，预留 12px 间距。
- 面板最大高度为视口高度减去导航栏、顶部与底部留白；内部内容独立滚动。
- 顶部标题、标签页、语言与搜索工具、底部跟随区域保持固定，只有内容区滚动。

### 3.3 窄屏、剧场模式与全屏

| 场景 | 布局默认 |
| --- | --- |
| 宽度 960–1279px，或右侧不足 380px | 将面板放到播放器下方，与视频信息区保持文档流布局；默认内容高 520px，不遮播放器 |
| 宽度低于 960px | 下方面板占可用宽度；左右内边距 12px；内容高取 420px 与可用视口高度的较小值，低高度场景改为自然高度 |
| 窗口很矮 | 优先保留输入与必要操作，减少固定区域，允许面板随页面滚动，不形成只能显示一行正文的内容窗 |
| YouTube 剧场模式 | 面板切到播放器下方，不占剧场播放器的画面位置 |
| 全屏播放 | 页面入口自然不可见；不强制退出全屏。全屏内快捷笔记浮层是否能可靠呈现列为能力测试项，失败时先保存草稿并在退出全屏后提示，不承诺已支持全屏浮层 |

拖动宽度设置只在当前电脑保存；离开视频页撤下所有插件页面 UI。浏览器放大时按可用 CSS 空间重新选择布局。

## 四、逐字稿界面

### 4.1 结构与正文

- 标签页下方显示“原文／中文／中英双语”分段控件，每项高 32px，当前模式使用底色与选中状态。
- 第一版初始模式暂定中英双语，之后记住用户选择；这是设计默认，用户未亲自指定初次默认值。
- 搜索框高 36px，支持当前可用原文或译文关键词，显示命中数量和上一条／下一条；未生成的译文不伪称已搜索。
- 每段时间放在上方，占 18px 行高，距离正文 4px。双语之间 6px；段落容器上下 12px、左右 12px，避免时间列挤压正文。
- 当前播放段使用 3px 强调色左竖线与浅色背景，保留至少 9px 文字内边距；高亮不改变字号、行高或容器尺寸。
- 鼠标悬停显示编辑图标；键盘聚焦时同样可用。用户不悬停时，工具不反复占据正文。
- 只显示所选模式需要的正文。AI 梳理始终默认中文，不随模式变化重新生成。

### 4.2 跟随与跳转规则

- 跟随模式使当前段位于内容可见区约上方三分之一处，留出后续内容；当前段已处于合理可见范围时不做小幅抖动滚动。
- 用户滚轮、触控板、拖动滚动条或键盘主动浏览后进入自由阅读。程序引起的定位滚动不能误判为用户操作。
- 自由阅读时继续计算当前高亮，只停止自动滚动；底部固定栏高 48px，显示“自由阅读”和主按钮“跟随”。
- 已跟随时显示“正在跟随”，按钮仍可用于重新定位；不要仅通过禁用按钮传达当前状态。
- 点击正文或时间戳跳转到该段开始并播放，默认恢复跟随。若浏览器拒绝播放，位置保留并显示“已定位，点击视频继续播放”，不能显示播放成功。
- 拖动选词、已有非空选区、点编辑图标、输入编辑、点击选词工具条均不得触发视频跳转。
- 空白时段保留视频当前位置提示，不错误高亮未来段；广告期间暂停正片跟随并提示“广告播放中”，不将广告时钟用作正片时间。

### 4.3 加载、空状态与失败

| 状态 | 可见内容与动作 |
| --- | --- |
| 首次打开、尚未处理 | 当前视频标题、真实阶段提示和进度条；工具不显示可误操作的假字幕 |
| 正在获取已有字幕 | 不确定进度条与“正在获取字幕”，无虚构百分比 |
| 无字幕，等待生成 | “未找到可用字幕，正在生成逐字稿”；如果需确认费用则先停在明确确认状态，不假称已开始 |
| 正在翻译 | 能计算已完成段数时显示真实进度；按需显示已完成内容并标明“翻译中”，不将未完成区当成全部结束 |
| 只有原文可用 | 原文可读；中文／双语模式明确显示译文待处理或失败，允许重试 |
| 获取失败或额度不足 | 中文说明、重试或查看设置入口；已存在的笔记与缓存仍可访问 |
| 视频切换 | 立即显示新视频标题与新视频加载状态，旧稿退出当前视图；异步旧请求不得回填 |
| 视频身份未确定 | “正在识别视频”，不显示上一个视频标题，也不允许把新笔记错误绑定到上一个视频 |

进度条高度 4px、圆角 2px，状态文字 13px；详细说明可展开，默认不向用户展示接口字段、堆栈或服务内部编号。

## 五、笔记界面与快捷记录

### 5.1 笔记列表与已保存内容

- 默认只显示当前视频的笔记，按时间点升序；同一时间按创建顺序。标题处显示笔记数。
- 每张卡片包含起止时间、双语引用、灯泡输入内容、问号输入内容、保存状态和编辑入口。
- 中英文直接排列，不添加“英文原文”“中文翻译”标签。
- 用户输入区用 18px 灯泡／问号 SVG 标识；无常驻“我的理解／我的疑问”文字。输入框允许简短占位提示“写下想法…”和“留下疑问…”，填写后提示消失。
- 已保存笔记仍可编辑原文引用、译文引用、理解和疑问。修改引用只改变这条笔记的引用，不反写逐字稿。
- 编辑态提供“完成”与“取消本次修改”；输入过程中保存草稿，完成后持久保存并回到阅读态。保存失败保留输入并显示重试，不显示“已保存”。
- 自动保存状态在实际本地写入成功后显示；不弹出打断式成功对话框。
- 切换标签或收起面板不清空编辑草稿。多个笔记编辑草稿按笔记标识分别保存，不相互覆盖。
- 删除不是本轮新增核心需求；若后续增加，必须独立设计可撤销与确认流程，不把编辑入口兼作删除。

### 5.2 轻量快捷笔记窗口

快捷笔记窗口是页面内非模态对话框。默认位于视口右下方，边距 20px，宽 400px，最大高为视口高减 40px；窄屏宽度取 `calc(100vw - 24px)`，边距 12px。

```text
┌─────────────────────────────────┐
│ 记笔记                      ×  │
│ 当前摘录视频标题               │
│ 08:42–09:06                    │
│ English sentence...            │
│ 对应中文……                    │
│                                │
│ [灯泡] 写下想法…               │
│                                │
│ [问号] 留下疑问…               │
│                                │
│ 草稿已保存           [完成]    │
└─────────────────────────────────┘
```

- 在支持的视频页，面板从未打开、已关闭或已打开时，快捷键行为一致。
- 按键瞬间冻结视频标识、标题和正片时间；视频随后继续播放不改变这次摘录的时间。
- 默认不暂停视频，也不重排主面板；这是减少观看中断的设计默认。用户可直接操作原播放器暂停。
- 有当前视频字幕缓存时立即摘录对应段；没有缓存时先创建待补全草稿，显示“正在补全此时刻的双语摘录”，允许立即输入想法或疑问。
- 只补全当前笔记的引用，不自动生成整段 AI 摘要；字幕供应商仍可能需要获取或处理全片，额度提示按实际请求计算。引用待补全失败时保留用户输入、视频链接和冻结时间，提供重试。
- “完成”保存后关闭窗口；关闭按钮与 `Escape` 收起窗口并保留草稿，不把关闭等同于删除。
- 自动把焦点移到想法输入框；`Tab` 可移到疑问与完成按钮。非模态窗口不锁定整个页面焦点，视频控制仍可操作。
- 已有未完成窗口时再次按快捷键，默认聚焦现有窗口并提示“先完成这条笔记”，不悄悄替换摘录；该行为作为防丢输入的设计默认。
- 切换到另一个 YouTube 视频时收起旧视频窗口并保存其草稿。新视频可创建新笔记，旧草稿不改成新视频来源；返回原视频后可恢复。
- 离开支持视频页时不显示窗口，但草稿保存在原视频下。
- 快捷键实际组合由技术方案与冲突测试确定；界面读取实际配置展示，不把示例按键硬写到提示。快捷键范围为当前支持的 Chrome 视频标签页，不承诺在其他应用全局截取。

### 5.3 划词摘录

- 鼠标选中非空逐字稿文字后，在选区上方或下方 8px 处显示 32px 高“做笔记”工具条，不盖住已选文字、不超出视口。
- 点击工具条打开同样的轻量笔记窗口，保持选区来源和时间关联。
- 默认保留用户精确选中文字，并附所属完整段的对应另一语言；原文与译文的局部词组不承诺一一对应。该粒度仍属于待样本验证的设计默认，不能伪造精确对齐。
- 跨多个段落时保留段落边界与各自来源时间，不把不连续片段编造成一句原话。
- 选择区域改变、用户清除选区、视频切换、进入编辑态或离开面板后，工具条收起。
- 只在本插件逐字稿选区显示入口，不劫持 YouTube 页面其他文字选择。

### 5.4 来源修改与用户修订

- 笔记引用保存摘录时快照。来源修改后显示轻量提示“来源有更新”与“查看差异”，不自动替换引用。
- 差异视图以“当前引用／来源新版”为短标签，逐行或逐段展示变动；新增与删除同时使用符号和颜色。
- 窄面板默认上下对照；宽度允许时再并排。理解和疑问仍在原卡片保留，不进入引用替换范围。
- 操作明确为“更新引用”和“保留原样”。保留后不重复提示同一个来源版本；来源再次变化可再次提醒。
- 若用户还修改过笔记引用，额外提示“这条引用有你的修改”；更新前清楚展示替换范围，不静默覆盖手动修订。
- 原文修改后默认保留现有译文并标“待核对”，手动重译单独触发；这是保守设计默认，须和技术方案、用户后续判断保持一致。

## 六、AI 梳理界面

顶部标签暂称“AI 梳理”，内部顺序为“概览、视频脉络、金句、方法”。“视频脉络”仍为候选栏目名，不显示“第一章、第二章”。

- 顶部概览为 2～3 句、约 100 字的全片总结。其后显示全片切片粗判断，汇总各段内容独立性，不预测流量。
- 视频脉络卡片的首行是时间范围，随后是主题标题；正文分别回答内容、问题、应用场景与切片建议。
- 卡片默认展开内容介绍，其余内容可展开；全部展开和折叠提供统一入口，用户不必连续点几十次。
- 按 2026-09-21 最新确认，“切片建议”第一版只给全片总判断和每段粗判断（建议切片／有条件建议／不建议单独切片）与价值、上下文条件。主题时间用于回看，不冒充精确切片范围；详细切片规划后续再做。不提供“剪辑”“生成视频”或“下载片段”按钮。第一版固定依据文字，紧邻显示“基于逐字稿”，不宣称已看过画面。
- 金句按反直觉洞察、惊人事实、轶事、点透本质筛选；双语引用配可点击的来源时间，不设“跳转原文”按钮。淡色双页图标默认复制双语，旁边小箭头可选中文或原文；有复制成功／失败反馈。惊人事实保留讲者陈述性质，不表示已核实。方法卡片使用中文名称与说明。应用场景用 2～3 句交代具体处境与用法，来源标注“讲者明确”或“AI 延伸”。
- 视频脉络之后增加知识清单，逐项展示需要理解什么、视频中的作用和可点击时间；前置知识在独立折叠小块中说明必要基础、程度与用途，无需基础不凑数。
- 时间入口跳转到对应视频位置并播放；“加入笔记”保存对应引用和来源，不自动填入用户的理解与疑问。
- 生成由用户明确操作触发；面板打开、语言切换和快捷摘录均不隐式重生成已有 AI 内容。
- 空状态使用简短说明与“生成梳理”按钮。生成、失败、部分完成、缓存可用分别显示，不让失败遮掉已保存结果。

## 七、编辑、设置和导出

- 逐字稿编辑采用当前段内联编辑；原文与译文分别可编辑，双语模式允许同时核对。完成／取消按钮只在编辑态显示，编辑时正文不响应跳转。
- 中文手动修正立即成为用户保存的版本，不自动触发重新翻译，也不能被在途旧翻译覆盖。
- 设置为专门的完整网页，在独立 Chrome 标签页打开；面板齿轮与 Chrome 扩展选项均进入同一页面，离开 YouTube 后也可以主动打开。
- 设置栏目包括常规、LLM 服务、字幕与外部 API、任务与模型、系统钥匙串。密钥输入只放在独立扩展设置页，不在 YouTube 页面 DOM 内收集。
- 系统钥匙串栏目展示“组件未安装／组件可用／版本不兼容／等待系统授权／钥匙串锁定／授权被拒绝／启动失败”。提供安装说明、检测和重试；组件空闲未运行不报离线。API key 保存后清空输入，仅展示已配置状态，不提供配对码或插件解锁密码；系统密码只在 macOS 系统窗口输入。已有缓存和笔记仍可用。首次安装、授权与升级体验须真实验证。
- 导出窗口分别选择“逐字稿／笔记／AI 梳理”，默认不一次全部勾选；逐字稿可选原文／中文／双语与时间戳。
- 笔记默认 Markdown，逐字稿默认 TXT 或 Markdown，是本版设计建议。笔记导出保留双语、来源、时间、理解和疑问；待补全或失败内容明确标记，不隐瞒缺项。
- 用户导出完整中文或双语逐字稿而仍有缺失时，展示缺失情况，并允许先补齐再导出；不能把部分文件称为完整。
- Obsidian 直接写入不出现在首版可点击操作中。未来能力可写入文档，避免用无效按钮占据主界面。

### 7.1 独立设置页布局

- 页底提供可见的保存区域；有未保存更改时提示，不能把表单中输入的值自动当成已启用配置。

### 7.2 LLM 与外部服务交互

- LLM 服务支持连接名称、实际支持的协议、Base URL、掩码密钥输入和默认模型，模型列表不可用时保留手动输入。
- “任务与模型”分别选择翻译模型和 AI 梳理模型，默认共用；Supadata 独立选择为字幕来源，不要求用户填 LLM 模型来获取已有字幕。
- Supadata 卡片提供密钥、字幕模式、允许生成与限制及测试状态；其他尚未适配服务不放无效表单。
- 测试状态显示未测试、测试中、模型可用或明确失败原因及时间。网络通但模型不可用时不能显示全部成功。
- 测试使用当前表单，但不自动保存；保存也不等于测试通过。测试按钮说明可能产生少量调用费用，不默认上传私人视频内容或笔记。
- 已保存密钥仅显示状态，不回填或提供查看完整 key；空输入表示不替换。保存成功后清空新输入，失败保留旧有效连接。环境变量来源显示只读来源说明。
- 切换模型不自动重生成逐字稿和摘要；当前运行任务与结果保持其原配置关联。
- 页面表单细则、凭据保存和服务能力边界以 [service-settings.md](service-settings.md) 为准。

## 八、动效、键盘与无障碍

- 按钮状态变化 120ms，面板展开和轻窗出现 160ms；不使用弹跳和长滑入。
- 跟随滚动上限约 180ms，快速拖动视频时立即定位，不能排队播放旧滚动动画。
- 尊重 `prefers-reduced-motion`：关闭非必要过渡、改为直接滚动；加载状态仍以文字说明。
- Tab 按逻辑顺序访问入口、标签页、语言模式、工具、段落操作与底栏。选中段落的跳转可通过明确按钮或键盘触发，不要求用户只使用鼠标正文点击。
- 标签页使用标准选中语义和方向键切换；弹窗有可读名称。仅真正阻止背景交互的差异确认对话框使用模态语义与焦点约束。
- 理解图标辅助名称为“理解或想法”，疑问图标为“疑问”；编辑、关闭、导出图标各有对应中文名称。辅助名称不等于常驻视觉标签。
- 保存、失败和视频切换使用温和状态播报；每次播放段高亮不反复向屏幕阅读器播报，以免盖住视频声音。
- 焦点轮廓 2px、偏移 2px，不能被卡片圆角截断。关闭窗口后焦点回到触发入口或当前视频的合理位置。
- 正文目标对比度至少 4.5:1，必要非文字控件和焦点至少 3:1；必须实际测量，不能仅凭本配色表宣称已满足。

## 十、本地翻译与主动大模型翻译

- 普通翻译优先本地，首次准备阶段显示模型下载状态与真实进度；未验证或不支持不能显示可用。
