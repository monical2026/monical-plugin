## 一、目标与版本范围

帮助用户在 Chrome 中看懂英文 YouTube 视频，通过逐字稿、中文 AI 内容梳理和个人笔记，减少暂停、重复观看及切换笔记工具的操作。

第一版仅供个人在当前电脑上使用，优先保证流畅性和笔记可靠保存。用户已确认第一版仅依据带时间的逐字稿进行翻译和 AI 梳理，不分析视频画面、PPT、图表或屏幕操作。教程仍可整理讲解文字，但不承诺补全只在画面中出现的操作步骤。画面理解留待后续评估，不作为第一版交付条件。未来公开产品时再支持多用户；跨设备同步、直接接入 Obsidian、对个人笔记进行后续 AI 整理放到后续版本。

## 二、已确认需求

### 1. 语言与显示

- 逐字稿提供“原文”“中文”“中英双语”三种模式，只展示当前所选模式对应的内容。
- 按所选模式处理需要的内容，原文模式不以完成中文翻译作为展示前提。
- AI 输出语言独立于逐字稿模式，默认固定为简体中文。
- 切换逐字稿语言不改变已有 AI 内容，不自动重新生成 AI 摘要。
- 笔记摘录保留中英文对照；个人理解与疑问按输入原样保存。
- 原文模式下尚无译文时，按实施默认先保存来源和输入，再补齐对应译文；未补齐前明确标记状态。

### 2. 字幕获取与加载

- 打开视频并启动插件后，先获取字幕，再按所选模式翻译和展示。
- 没有可用字幕时，每次先展示该视频的预计生成积分、估算依据和处理范围，用户点击确认后才向外部服务提交生成请求；取消后保留已有笔记。
- 抓取与处理期间展示加载界面、进度条及当前处理阶段。
- Supadata 作为优先验证的字幕服务候选，尚未完成接口实测或最终选型。
- 必须区分获取已有字幕、生成字幕、中文翻译和 AI 分析的能力与额度。

### 3. 逐字稿分段与播放联动

- 逐字稿由时间戳和文字小段组成，原文与译文保持对应关系。
- 使用本地程序整理阅读分段；2026-09-12 已确认统一重组、可靠断句、向后比较和长度软目标，具体阈值及实现效果待样本验证。
- 播放期间高亮当前段落；跟随状态下自动滚动到当前内容。
- 用户可以自由上下滚动，查看历史或后续内容。
- 手动滚动后停止自动拉回，但当前播放段落的高亮状态仍随视频更新。
- 底部提供“跟随”按钮；点击后定位当前播放段落并恢复跟随。
- 视频暂停时也能翻阅和点击“跟随”定位暂停位置。
- 直接点击逐字稿段落文字，视频跳到对应时间点并开始播放。
- 拖动划词与单击跳转必须区分，选中文字不得误触视频跳转。

### 4. 笔记摘录与输入

- 快捷键摘录当前播放片段，将双语内容及时间关联插入笔记。
- 主面板未打开时也能在当前 YouTube 视频页通过快捷键记录，使用独立轻量笔记窗；扩展本身仍需启用。
- 摘录后弹出窗口，允许补充自己的理解、想法或疑问。
- 阅读逐字稿时，鼠标选中文字后出现“做笔记”入口，点击即可摘录。
- 个人理解与疑问可以分别填写，也可以留空。
- 笔记保留视频来源及时间关联，便于后续回看和导出。
- 插件中的双语摘录直接上下显示，不显示“英文原文”“中文翻译”标签。
- 理解与疑问使用简洁 SVG 图标，不显示常驻的“我的理解”“我的疑问”标签。
- SVG、字体大小和布局采用 design.md 中的设计默认，实际观感仍需原型及人工验收。
- 保存后的笔记仍可编辑，包括摘录文本、理解和疑问；修改笔记摘录不反向修改逐字稿。

### 5. 编辑与摘录版本

- 逐字稿原文和中文译文均允许手动修正。
- 修改中文译文后直接保留修改结果，不触发重新翻译。
- 已保存的笔记摘录保留摘录时的原文和译文版本。
- 对应来源文字修改后，提示笔记来源已更新，不静默替换摘录。
- 用户可查看修改差异，自行选择更新引用或保留原样。
- 更新引用时，不自动修改用户自己的理解和疑问。
- 修改原文后的实施默认：保留已有译文，标记待核对，由用户手动触发重译，不静默覆盖人工修正。
- 若笔记摘录也已手动改过，更新来源时展示差异，由用户选择，不自动覆盖。

### 6. AI 内容梳理

- 提供整个视频的中文摘要及内容框架。
- 每个内容分段展示：内容标题、起止时间、内容介绍、解决的问题、应用场景。
- 提供全片与每段是否适合独立切片的粗判断及理由，详细切片范围规划后续再做。
- 提取视频中的金句及有效方法，并关联来源时间。
- 不使用“第一章、第二章、第三章”作为主要展示标题。
- 暂采用“视频脉络”作为设计默认栏目名，使用“时间范围＋具体内容标题”，可在视觉验收时调整。
- 用户已确认第一版只提供建议时间范围和理由，不剪辑、不生成或下载短视频文件。

### 7. 保存与导出

- 第一版在当前电脑保存笔记，刷新或重新打开视频后能够恢复。
- 支持导出完整逐字稿，提供原文、中文、双语选择。
- 支持导出个人笔记，保留双语摘录、理解、疑问、视频来源及时间信息。
- 导出默认采用 Markdown 笔记，以及 TXT/Markdown 逐字稿；属于可调整实施默认。
- 未来增加直接写入 Obsidian 知识库；当前不把文件导出等同于自动同步。

### 8. 页面入口与视频切换

- 插件仅用于 YouTube 视频；其他网页不显示插件页面界面。
- YouTube 视频下方的合适空余位置放置小入口按钮，点击打开主面板，避免遮挡播放器和已有操作。
- YouTube 内切换到不同视频时，逐字稿随当前视频更新，AI 内容和笔记也按视频隔离。
- 站内跳转、自动连播、播放列表切换、前进后退、直接刷新均须验证；同页切换不依赖整页刷新。
- 切换后旧视频的迟到请求不能覆盖当前视频；返回旧视频时恢复其自己的内容。
- 离开视频页时撤下入口、面板及笔记窗；保存中的草稿保持原视频归属，不转移到新视频。
- 多标签页各自跟随对应视频，快捷键只作用于当前活动的有效视频标签页。
- 用户已确认第一版支持普通 YouTube watch 视频页；Shorts、正在直播的视频及其他网站嵌入的 YouTube 播放器留到后续。普通视频的剧场／全屏表现仍需实测，不把它们等同于其他页面类型。

### 9. 开发、测试与提交顺序

- 先完成设计、技术方案、测试方案与空白反馈文档，再进入代码实现。
- 实现后按 test-plan.md 执行，在 test-feedback.md 记录结果、问题、修复方式、回归证据及下一步。
- 全部范围内测试通过且用户明确人工验收通过后，再 Git 提交并推送 GitHub。
- 测试未执行、受阻或未完成人工验收时，不记录为通过，也不提前提交推送。
- GitHub 目标仓库和可见性目前未确定，发布前再确认；当前仓库尚未配置远程地址。

### 10. 独立设置网页与模型连接

- 用户明确要求专门网页设置 LLM 及其他外部服务 API，在 Chrome 独立标签页打开，不依赖当前是否观看视频。
- 设置页可填写 LLM 连接名称、接口地址、API key、默认模型，提供模型列表或手动输入、测试连接与保存配置。
- 普通翻译优先验证 Chrome 本地 Translator API；LLM 翻译由按钮主动触发，可与 AI 梳理共用或分别选择模型；AI 输出仍默认中文。
- Supadata 作为独立字幕服务配置，凭据、字幕模式及测试与 LLM 分开。
- 页面填写的密钥经按需组件安全存入 macOS 系统钥匙串，环境变量仅保留开发/受管来源；不要求用户在源码中填 key。
- 第一版兼容协议、具体字段、错误与成本提示属于 service-settings.md 所列实施默认，不承诺尚未测试的任意供应商均兼容。
- 修改设置不自动重生成已有结果，记录配置版本；未配置 LLM 时仍可读已有原文和编辑本地笔记。

## 三、实施建议与质量约束

以下为用户授权完善计划后的实施默认与质量约束，不声称是用户逐条亲定。后续验证如需调整，记录原因。

- 分段优先使用句子边界、标点和停顿，合并过短碎片，限制过长段落；保留底层时间映射，避免编辑文字后跳转失效。
- 原文、译文、笔记引用使用稳定关联，记录来源版本和摘录快照；重新分段时也需明确旧笔记如何定位。
- 服务未提供真实百分比时使用不确定进度条和阶段提示；有可计算进度时再显示百分比，不虚构进度。
- 翻译与 AI 分析失败时支持清楚的错误提示及重试，避免重复请求导致重复计费。
- 保存可复用的处理结果，减少重复打开视频的等待和额度消耗。
- 金句须能回到原文核对；AI 推导的应用场景与讲者明确表达的内容应区分。
- 第一版切片建议仅依据逐字稿，明确判断依据，不宣称已检查画面效果。
- 图标支持悬停提示、键盘聚焦提示及辅助阅读名称，同时保持默认界面简洁。
- 外部服务凭据使用环境变量或安全凭据机制，不写入源码、导出文件或日志，不把共享服务密钥打包进扩展。
- 超额处理和自动充值策略须明确；不默认开启付费处理。
- 关闭面板只关闭显示，不关闭快捷键记录能力；不因隐藏面板自动启动字幕或整份 AI 分析。
- 快捷记录立即冻结视频与时间；字幕尚未取得时先保存想法和时间来源，随后补引用，不丢输入也不编造文字。
- 默认打开笔记窗不暂停视频，用户可手动暂停。页面切换时草稿自动保存并保留原视频关联。
- 编辑、划词与点击跳转严格区分，编辑笔记或逐字稿不得意外改变播放位置。
- 按视频、源文字版本及配置复用结果，修正人工文本时防止后台旧翻译覆盖。
- 清理缓存、卸载和跨设备备份的边界需要清楚说明；第一版不实现隐式清除个人笔记。
- 补充本地逐字稿搜索、AI 条目加入笔记和可查看的保存状态，均作为本轮完善的实施默认；搜索未生成的译文不得显示虚假的完整结果。
- 新摘录及编辑旧笔记先自动保存草稿，“完成”后形成正式笔记或新修订；关闭窗口保留草稿，“取消本次修改”恢复编辑前版本。
- 当前视频已有未完成笔记窗时，再按快捷键聚焦现有草稿，避免替换来源或丢输入；切换视频后可以建立新视频的草稿。

## 七、已确认的节省额度策略

- 使用量：每周约 5 个视频，单个约 40 分钟、1 小时或更长，无固定上限。按月约 20–22 个是估算，不是用户提供的精确用量。
- 优先获取已有字幕并缓存；无字幕生成每次需先展示预计消耗并确认，不提供默认勾选或永久跳过，不自动切换为可能计费的生成模式。直接从 YouTube 获取的稳定性须验证，Supadata 是现有候选服务，不能把直接抓取写成已实现。
- 默认翻译尽量不消耗云端 LLM token；优先验证 Chrome Translator API。它不是浏览器整页翻译按钮，也不等于 Google Cloud Translation。
- 本地能力验证通过后用于中文/双语显示及双语摘录补齐；首次模型下载提供进度。不可用时保留原文和笔记，提示重试或主动选择 LLM，不自动付费回退。
- 段落提供“用大模型翻译”；全文操作独立展示范围与费用提示。结果作为候选译文，由用户选择替换，保留人工修订及笔记快照规则。
- AI 摘要、视频脉络等仍由用户主动触发 LLM；不把本地翻译称为整个插件完全免费。
- 在所有视频都有可获取字幕、每份只请求一次的假设下，Supadata 已有字幕约 20–22 积分/月；生成、失败请求、重复请求和 LLM 费用另计，价格变更以官方信息为准。

- 用户最新确认：保留引擎切换设计，先验证本地翻译质量；只有本地效果满足要求后再确定默认使用。本地不足时报告结果，等待用户明确指令才接入 client=gtx，当前不调用、不自动回退。

- 本地翻译验证结果：Chrome 独立扩展文档可调用，但 8 组定向样本存在口语及术语错译；见 [评估记录](local-translation-evaluation.md)。暂不确定默认引擎，client=gtx 等待用户指令。

### 已确认：逐字稿分段基础方案（2026-09-12，0.1.7 已实现待验收）

用户确认以下基础方向，并要求先完成纯规则版本、查看实际效果后再讨论 SaT。0.1.7 已接入新获取字幕及旧缓存的显式预览入口；不自动修改旧缓存。后续版本记录中的“分段待确认”描述保留为当时状态。

1. 统一处理所有字幕来源：YouTube 直接字幕、Supadata 已有字幕和生成字幕进入同一套本地重组流程，再翻译和展示。
2. 统一重组：原始字幕条目不等于句子，允许跨条目合并、在条目内部重新断句；保留原始文本及来源时间映射。
3. 可靠断句：完整句优先，处理缩写、小数、姓名和引号等误切情况。可靠说话人变化阻止跨人合并；没有说话人数据不猜测身份。字幕时间间隔只能辅助判断，不能冒充真实语音停顿。
4. 向后比较：比较后续完整句的多种组合，减少残余短段；句子完整性和可靠说话人边界优先于段落长度均匀。
5. 长度软目标：约 220 英文原文字符作为待验证参考，不是硬上限；长句允许超过目标，短句可以组合，真实短回应可以独立。字符数、时长均不得单独触发句中硬切。

当前无新增依赖，使用本地标点规则和动态规划；每个起点最多比较后续 32 个完整句，英文／中文软目标分别为 220／100 字符。参数为实施初值，仍需真实视频调优。SaT 按用户要求暂不引入；音频说话人识别和逐段人工合并／拆分入口继续延后。缺标点且无法确认边界时优先保留较长段落，不补写原话。

后续验证使用真实字幕检查破句、过度合并、漏字重字、时间定位和本机开销。字幕只给整条时间时，句内跳转只能使用来源字幕精度，不能宣称逐词精确。升级需保护手改内容、译文和笔记快照，明确新旧映射，不直接覆盖旧引用。
